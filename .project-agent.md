# Project Agent — Blender AI Orchestration

## Identity
- **Product:** Blender AI Orchestration Foundation
- **Goal:** AI drives Blender to build 3D, animation, render — via MCP (interactive) + headless CLI (batch).
- **Owner:** Jang

## Tech Stack (binding)
- Blender 5.2.0 LTS local (`/Applications/Blender.app/Contents/MacOS/Blender`) — matches the target of the `knowledge/` KB. Upgraded from 4.3.2 on 260728, regression pass.
- MCP: `blender` server = ahujasid/blender-mcp at `/Users/jang/blender-mcp` (socket addon port 9876)
- Headless: `blender -b` + scripts in `scripts/` (Cycles; choose CPU/Metal with a profile measured for the scene, do not assume the GPU is faster by default; do not rely on EEVEE for the current macOS batch route)
- Asset construction: Blender-native data API, bmesh, modifiers, sculpt, and local project scripts only.
- No new generated/retrieved vendor mesh, paid credit, hosted-model call, or external asset download may enter production.
- Exception: an already-local artifact may be salvaged as a frozen scaffold when the user explicitly selects it; rebuild must be self-contained, provenance-recorded, repaired in Blender, and make zero further service calls.
- Local retopology gate: user-selected QRemeshify 1.1.0 may process a frozen scaffold offline through `scripts/run-qremeshify.py`; binaries are hash-pinned, GPL-3.0-or-later, and must pass macOS quarantine approval plus topology/visual gates before entering a build.

## Binding Rules
1. **bpy code: prefer the data API, avoid `bpy.ops`** unless unavoidable. Details: `knowledge/00-foundations/bpy-scripting-core.md`. Current skills: `blender-agent-core`, `blender-image-to-3d`, `blender-knowledge-workbench` — there is no other skill.
2. **Every pass must end with verification along the cheap → expensive ladder**: numeric asserts (postcondition in `AGENT_OK`) first; images (`preview_render(engine="EEVEE")`, viewport screenshot, turntable) only for what the eye alone can judge, and the expectation must be written down before looking. The last step of a build always has visual verification. Part that will be printed/manufactured: `scripts/production-gate.py` exit 0 with the build's `spec.json` before delivery.
3. **Socket names/API** — introspect at runtime and use `knowledge/20-shading/materials-pbr.md`; do not rely on names from another version.
4. **The MCP addon must Connect first** (Blender sidebar `N` → BlenderMCP → Connect to Claude) — if a tool returns a connection error, tell the user to open the addon, do not retry blindly.
5. **Purpose, then contract before detail**: ask the deliverable purpose once — `render-only` / `print` / `both`, recommendation `both`; no answer → `purpose: assumed both` recorded in `state.md`. A production part must have `builds/<slug>/spec.json` (schema `specs/build-spec.schema.json`) before detail is built; missing dimensions/payload/duty → `request-input`. Purpose `print`/`both` → **form gate** at the end of phase 2 and **final gate** at delivery (`AGENTS.md` §Mandatory loop 5b); **delivery** media only after PASS or a `GATE WAIVED <time> "<owner words>"` line — verification previews and per-pass clay renders are exempt.
6. **Decide success by the sentinel** `AGENT_OK`/`AGENT_FAIL` (last stdout line), not by Blender's exit code or the words "executed successfully".
7. Downloaded assets → `assets/`, render output → `output/` (both gitignored if there is a repo).
